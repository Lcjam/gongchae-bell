# ADR-0013 복원 후 해지 유지: 호스트 파일 대장

- **상태**: 채택 (2026-11-08, 사용자 결정)
- **맥락**: 백업은 하루 1회다. 백업에서 복원하면 마지막 백업 이후에 해지한 구독이 되살아나 다시 발송될 수 있다 (PRD §7 "백업 복원 후 해지 유지").
- **선택지**: (a) OCI Object Storage에 동기 기록 / **(b) 호스트 파일 대장** / (c) 복원할 때 구독 전부 폐기
- **결정**
  - 해지할 때 구독 행 잠금 아래에서 호스트 디렉터리(DB 볼륨과 분리)의 `erasure.log`에 `구독 UUID, 시각` 한 줄을 추가하고 fsync한 뒤 DB에서 삭제한다. UUID만 남기므로 개인정보가 아니다
  - `erasure.log`는 DB 덤프와 함께 restic으로 백업한다(ADR-0012)
  - 복원 절차: **발송을 멈춘 채** 덤프를 복원한다 → 대장의 UUID를 모두 다시 삭제한다 → 검증한 뒤 발송을 재개한다
- **결과**
  - 가장 흔한 사고(잘못된 마이그레이션, 실수 삭제, DB 손상)에서는 해지가 완전히 유지된다. 구현은 파일 쓰기 한 줄과 복원 명령 하나다
  - **한계**: VM 자체가 사라지면 마지막 백업 이후(최대 약 24시간)의 대장도 사라진다. 그 사이 해지한 사람에게 다시 발송될 수 있다 → 처리방침과 runbook에 이 한계를 적는다
