# ADR-0014 초기 설정값

- **상태**: 채택 (2026-11-08). **모두 초기값**이다. 운영하면서 조정하고, 바꿀 때마다 이 문서와 CHANGELOG에 이유를 남긴다. 성능이나 가용성 목표가 아니다.
- **맥락**: PRD는 만료, 재시도, 제한, 파기의 구체 값을 ADR에서 정하게 했다. 세 에이전트의 제안(codex, agy, claude)을 종합했다.

| 항목 | 값 |
|---|---|
| 정기 수집 | 매시 7분 (KST) |
| 이메일 묶음 / 디스코드 마감 임박 | 매일 08:00 / 09:00 (KST). 놓치면 당일 1회 만회 |
| 백업 | 매일 03:00, 보관 14일 |
| 확인 토큰 | 24시간, 1회 사용 |
| 미확인 구독 | 확인 토큰이 만료되면 삭제 |
| 비활성 구독 | 비활성화 30일 뒤 삭제 |
| 발송 작업 기록 | 완료 30일 뒤 삭제 (`notification_item` 중복 키는 구독이 살아 있는 동안 유지) |
| 외부 HTTP | 요청 타임아웃 10초, 최초 포함 최대 3회, 간격 2초와 4초. 429는 서버가 지시한 시간보다 일찍 재시도하지 않는다. 지시가 60초 이하면 기다리고, 넘거나 읽을 수 없으면 그 회차를 실패로 끝내 다음 회차에 맡긴다 (2026-11-15 추가: 큰 값에 스케줄 스레드가 묶이지 않게) |
| 공고 상세 수집 | 공고당 실패 3회 후 중단(예산 소진·종료는 세지 않음). 한 sweep에서 새 요청은 30건·10분까지만 시작한다(진행 중인 한 건은 끝까지, HTTP 상한으로 최대 약 150초 추가) (2026-11-15 추가: 실패한 상세의 무제한 재시도가 일 예산을 쓰지 않게) |
| 발송 회수 | `SENDING` 5분 초과 → `UNCERTAIN` 기록 후 `RETRY` |
| 구독 비활성화 | 디스코드 404 즉시. 이메일은 API가 수신 주소 오류를 돌려주면 즉시. 공급자 5xx와 연결 오류로는 비활성화하지 않는다 |
| API 예산 | 하루 500 경보, 900 자동 중단. 정기 수집 몫 72회(24회 × 최대 3회 시도)를 남겨, 상세와 최초 적재는 828에서 멈춘다 (2026-11-15 추가) |
| 요청 제한 | 신청·재발송·웹훅 테스트: IP당 10분에 10회, 대상(이메일·웹훅)당 1시간에 3회. 토큰 실패: IP당 10분에 30회 |
| 전체 발송 상한 | 이메일 하루 90통 (Resend 무료 100 미만), 디스코드 시간당 300회 |
| 종료 | graceful shutdown 30초, 컨테이너 종료 유예 40초. 수집 스케줄러도 진행 중인 회차를 30초까지 기다린다 |
| JVM | 힙 512MiB로 시작. 컨테이너 메모리 한도는 실측 후 정한다 |
| Prometheus 보존 | 1년 |

## 개정 (2026-11-16, #6 · 계약 12·13·14)
| 항목 | 값 |
|---|---|
