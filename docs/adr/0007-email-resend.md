# ADR-0007 이메일 발송: Resend HTTP API

- **상태**: 채택 (2026-11-08, 사용자 결정)
- **맥락**: 이메일 알림(확인 메일 + 하루 1회 묶음)에는 발송 서비스가 필요하다. OCI Email Delivery는 무료 한도가 문서끼리 충돌하고(월 3,000 대 한도표 0), 발송 리전도 보장되지 않아 제외했다.
- **선택지**: Resend / Brevo(하루 300, EU 저장, 무료 브랜딩, 로그 기본 무기한)
- **결정**: **Resend**를 HTTP API(`POST https://api.resend.com/emails`)로 호출한다. SDK 없이 JDK HttpClient를 쓴다. `Idempotency-Key`는 발송 작업 ID로 둔다.
- **결과**
  - 무료 한도는 하루 100통, 월 3,000통이다([공식](https://resend.com/pricing)). 전체 발송 상한을 하루 90통으로 둔다(ADR-0014). 이메일 구독자가 늘어 한도에 닿으면 유료 전환이나 서비스 변경을 다시 결정한다
  - **저장 위치가 미국이다** → 처리방침에 수탁자(Resend), 위탁 업무, 국외 이전을 고지한다(PRD FR-A6). 메일과 로그 보관 30일([공식](https://resend.com/security))도 함께 적는다
  - 사용자 도메인에 Resend 발신 인증(SPF, DKIM) 레코드를 등록해야 한다
  - 비동기 반송은 MVP 밖이다. API가 수신 주소 오류를 즉시 돌려주면 그 구독을 비활성화하고, 5xx와 연결 오류는 재시도만 한다(PRD FR-A5)

## 개정 (2026-11-16, #6 · 계약 12·13·14)
- `Idempotency-Key`는 작업마다 정한 UUID다. 결과 모름 시도가 있으면 **같은 키와 같은 요청 바이트**로만 재시도한다. 요청 전체의 SHA-256(`payload_sha256`)을 비교하고, 자격이나 해시가 바뀌었으면 보내지 않고 `UNCERTAIN`으로 끝낸다. 앞선 시도가 모두 확실한 거절(4xx, 429, 연결 수립 실패)일 때만 새 키를 쓴다. 공식 문서에 키 보관 24시간이 적혀 있다. "실패 응답은 키에 저장하지 않는다"는 공식 문서에서 확인하지 못해 전제로 쓰지 않는다.
- **수신 주소 오류 전용 응답이 공식 오류 표에 없다.** 그래서 이메일 구독을 응답으로 자동 비활성화하지 않는다. 400·422는 작업 실패, 401·403은 계정 오류로 지표에 남긴다. PRD FR-A5의 규칙은 유지하되, 지금은 그 조건에 해당하는 응답이 없다. 비동기 반송은 여전히 MVP 밖이다.
- 공유 상한 90은 공급자 기준대로 UTC 날짜로 세고, 시도마다 예약한다. 일 한도 429(`daily_quota_exceeded`)도 HTTP를 받았으므로 시도와 예약에 포함한다.
- 메일은 텍스트 본문만 보낸다(추적 이미지·링크 변형 없음). 발신 도메인의 열람·클릭 추적이 꺼져 있는지는 실사용 전에 확인한다. 자세한 것은 [#6 계약](../../collab/2026-11-16-implementation/claude-subscriptions-contract.md).
