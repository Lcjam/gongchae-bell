# ADR-0017 백업 보관: 실행 시각 기준 14일, 최후 사본 예외 없음

- **상태**: 채택 (2026-11-19, 사용자 결정 `collab/2026-11-19-recovery/04-user-retention-decision.md`). ADR-0012의 `restic forget --keep-daily 14 --prune`를 대체한다.
- **맥락**: PRD·ADR-0014의 "보관 14일"을 restic 옵션만으로는 지킬 수 없다. `--keep-daily 14`는 snapshot이 있는 마지막 14일을 센다. `--keep-within`은 최신 snapshot 기준이다. 둘 다 백업이 실패하는 동안 오래된 사본을 남긴다. 기존 스크립트는 백업이 성공한 뒤에만 forget했으므로 덤프나 업로드가 실패하면 정리 자체가 일어나지 않았다(#17 01·02 검토). 사용자는 "다음 실행 때 현재 시각 기준 14일을 넘은 사본을 모두 삭제하고, 복원 사본 0개도 허용"을 골랐다.
- **결정**
  - `backup.sh run`은 매 실행 시작 때 시각(UTC epoch)을 한 번 읽는다. `restic snapshots --tag gongchae-bell --json`을 `deploy/backup/expire-select.py`로 검사해 `지금 - snapshot 시각 > 14일`인 snapshot을 **전체 ID로** `restic forget`한다. 최신·마지막 사본 예외는 없다.
  - 그다음 `restic prune --max-unused 0`을 **매 실행** 돌린다. 기본값 5%를 허용하면 지운 snapshot의 데이터가 부분 사용 pack에 남을 수 있다. 전 실행의 prune이 실패해 남은 데이터도 다음 실행에서 지운다.
  - 같은 시각 기준으로 다시 목록을 받아 만료 대상이 0개인지 확인한다. 이 확인이 끝나야 덤프와 업로드로 넘어간다. 그래서 덤프·업로드가 실패해도 만료 사본은 이미 지워져 있다.
  - 목록을 믿을 수 없으면 아무것도 지우지 않고 실패한다(`RETENTION_SELECT_FAIL`). 해당하는 경우는 JSON이 아님, 배열이 아님, 64자리 hex가 아닌 ID, 시간대 없는 시각, `gongchae-bell` 태그 없음, 5분을 넘는 미래 시각이다. snapshots·forget·prune·확인이 실패해도 덤프 전에 멈추고 Healthchecks `/fail`을 보낸다. 보유기간을 지킨 것으로 세지 않는다.
  - 다른 태그 snapshot은 목록에 들어오지 않으므로 지우지 않는다. `BACKUP_KEEP_DAILY`는 없앴다. 남아 있으면 기동을 거부한다.
- **결과**
  - 실제 최대 보관은 "14일 + 실행 간격"이다(매일 03:00이면 약 15일). 14일 직전 사본은 다음 실행까지 남는다.
  - 백업이 14일 넘게 실패하면 복원 사본이 0개가 된다(사용자 수용).
  - 만료 실패(잠금·자격·네트워크·prune 오류) 동안은 그날 백업도 하지 않고 `/fail`로 알린다. 재시도는 다음 타이머 실행이다. 물리 삭제는 그 사이 지연된다.
  - restic 저장소에 접근할 수 없으면 삭제를 보장할 수 없다. 복구 전까지 경보가 계속된다.
  - 호스트에 `python3`이 필요하다(Ubuntu 24.04 기본 포함). 매일 prune에 따른 Object Storage 요청이 늘지만 작은 저장소라 감수한다(실측 전).
  - **PC pull(#17) 접점**: 네트워크 작업(`restic copy`) **전에** 로컬 저장소에서 같은 `expire-select.py` + 명시 ID `forget` + `prune --max-unused 0` + 재조회 검증을 먼저 수행해, OCI 연결이나 `restic copy`가 실패한 날에도 로컬의 14일 초과 사본이 남지 않게 한다. 이어서 `restic copy`(원래 snapshot 시각 보존, #17 02 검토) 뒤에도 같은 만료 재검사·정리를 수행해 14일 넘은 OCI 사본이 로컬에 재보관되지 않도록 한다. 어느 단계든 실패하면 보유기간을 지킨 것으로 세지 않고 경보·재실행으로 다룬다. PC가 꺼진 동안은 정리가 실행되지 않는다(사용자 고지 완료). 이번 변경은 서버 경로만 구현했다.
