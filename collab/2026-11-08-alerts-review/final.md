# 알림 요구사항 리뷰 · 조율자(claude) 종합

> 입력: [01-claude](01-claude.md) · [01-codex](01-codex.md) · [01-agy](01-agy.md). 대상: `docs/prd.md` FR-A1~A7
> 1라운드에서 의견이 대부분 겹쳤다. 갈린 것은 조율자가 정리하거나 사용자 결정으로 넘겨서, 2라운드(교차 비판)는 생략했다.

## 합의 (셋 다 지적) → PRD에 반영
| 항목 | 반영 내용 |
|---|---|
| 링크 프리페치 | 확인과 해지 링크의 GET은 확인 화면만 보여 준다. 상태 변경은 POST로만 한다 (claude, codex, agy) |
| 남용 방지 | FR-A7(발송 제한)을 **Must**로 올린다. 신청, 확인 재발송, 웹훅 테스트, 토큰 시도를 IP와 대상 기준으로 제한한다. 구독 여부가 응답에서 드러나지 않게 한다 (셋 다) |
| 개인정보 | 신청 화면에 목적, 항목, 보유 기간, 거부권과 거부 시 제한을 고지하고 동의를 받는다(제15조). 처리방침에 권리 행사 방법과 담당 연락처를 적는다(제30조). 상태별 파기 시점을 확정한다(제21조) (셋 다) |
| SSRF | URL을 파싱해서 https, 허용 호스트(`discord.com`, `discordapp.com`), 웹훅 경로를 정확히 검사한다. 리다이렉트는 따라가지 않고 사설·루프백·링크로컬 대역은 차단한다. 우회 입력을 테스트한다 (셋 다) |
| 동시 발송 | 발송 작업은 DB에서 원자적으로 선점한다 (`PENDING → SENDING` 조건부 갱신 또는 `SKIP LOCKED`). 수집 반영과 발송 대상 생성 사이에서 중단돼도 복구한다 (codex, agy) |
| 토큰 | 확인 토큰은 만료가 있고 한 번만 쓴다. 관리 토큰은 해당 구독만 다룬다. 둘 다 해시로 저장하고 로그에 남기지 않는다. 관리 화면은 `no-referrer`, `no-store`로 둔다 (claude, codex) |
| 원클릭 해지 | `List-Unsubscribe`와 `List-Unsubscribe-Post` 헤더를 넣는다 (Should). Gmail과 Yahoo의 대량 발신자 요건은 우리 규모에 바로 적용되지 않지만 좋은 관행이다 (claude, agy) |
| 출시 검증 문구 | "스팸함으로 가지 않는다"를 "테스트 계정에서 SPF/DKIM이 통과하고 받은편지함으로 들어오는 것을 확인하고 기록했다"로 바꾼다 (codex, agy) |
| 설정값 | 만료 시간, 재시도 횟수, 제한 횟수, 파기 시점의 **구체 값은 ADR에서 정한다.** PRD에는 규칙만 둔다. agy가 제안한 값(24시간, 분당 5회, 3회 등)은 ADR의 초안으로 쓴다 |

## 한 에이전트만 지적 → 반영
| 항목 | 출처 | 반영 |
|---|---|---|
| 비밀값 규칙 충돌 | codex | "비밀값은 환경변수로만"과 "사용자 웹훅 URL을 DB에 저장"이 충돌한다. 그래서 **서버 자격증명과 암호화 키는 환경변수와 Secrets에 두고, 사용자 웹훅 URL은 DB에 암호화해서 저장하며, 키는 DB와 백업에서 분리한다**로 정리한다 (CLAUDE.md도 같이 고친다) |
| 해지와 발송 대기의 경합 | codex | 해지하면 대기 중인 작업을 취소하고, 발송 선점 시점에 구독 상태를 다시 확인한다 |
| 같은 이메일 재신청 | codex | 새 신청이 기존 활성 구독을 덮어쓰지 않는다 |
| 디스코드 성공 판정과 멘션 | codex (공식 문서 인용) | `wait=true`로 메시지 생성을 확인하고, `allowed_mentions`로 자동 멘션(`@everyone` 등)을 막는다 |
| 위탁과 국외 이전 | codex | 발송 서비스(ADR)가 정해지면 수탁자, 업무, 국외 이전 여부를 처리방침에 반영한다 |
| 디스코드 404 | codex, agy | 웹훅 404는 즉시 비활성화한다. 429는 `retry_after`를 지킨다 |
| 알림 경계 조건 | codex | 발송 시각에 서버가 꺼져 있었을 때의 만회 정책, 마감 연장 시 재알림 여부, 조건 변경의 적용 시점, 긴 본문은 요약 + 목록 링크로 처리하는 것을 설계에서 정한다 |

## 갈린 의견 → 조율자 정리
| 쟁점 | 입장 | 정리 |
|---|---|---|
| 디스코드 구독자의 관리 링크 | claude: 테스트 메시지에 관리 링크를 넣자 / codex: 공개 채널에 오래 쓰는 토큰을 남기지 말자 | **claude 철회.** 관리 링크는 등록 완료 화면에 한 번만 보여 준다. 잃어버리면 **웹훅 URL을 다시 입력해서 관리**한다(URL 해시가 맞는지 확인). URL 자체가 비밀이므로 URL을 가진 사람이 관리 권한을 가진다 |
| 이메일 반송 | agy: 비동기 반송은 MVP에서 제외 / codex: 종류를 구분하고, 발송 서비스 동작은 미확인 / claude: ADR에서 정함 | MVP는 **발송 시점의 즉시 실패(SMTP·API 5xx)**만 처리한다. 비동기 반송은 발송 서비스 ADR에서 제공 방식을 보고 정한다 |
