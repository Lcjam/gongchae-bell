## 채택 근거와 범위

root는 보관된 두 JSON과 영속 DB를 독립 확인했다. 동일 하한에서 종료 조건을 보낸 1페이지는 totalCount 36,277/행 1,000/월 걸침 371/미래 시작 0/목표일 뒤 마감 0이고, 종료 조건을 생략한 1페이지는 totalCount 36,772/행 1,000/월 걸침 374/미래 시작 4/목표일 뒤 마감 381이었다. attempt 42·43은 BACKFILL 1차 SUCCESS이며 전체 예산 43이다. 추가 HTTP는 2회이고 세 번째는 사용하지 않았다.

종료 조건을 생략하는 시작일 하한 scan을 채택한다. 전체 raw 페이지의 검증과 목표 기간의 로컬 선별을 분리하며, 끝까지 하한·총수·중복·페이지 크기를 확인한다. 36,772를 목표 기간 적재 건수로 미리 주장하지 않는다. 실제 뒤 페이지에서 전제가 어긋나면 실패로 보고한다.

legacy 월별 완료는 새 전략에서 재사용하지 않는다. V4에 명시적 전략·scan generation·raw/적용 스냅숏·집계의 필요한 최소 열을 추가하고 M2는 V5부터 시작한다. prefix만으로 기존 열 의미를 바꾸는 안은 채택하지 않았다. restart는 새 generation이며 다른 세대 페이지를 섞지 않는다. 기존 22,733행·76회차·예산 이력은 보존한다.

## 새 테스트를 포함한 단일 수정 PR

신규 scan은 합본 테스트의 요청 계약도 바꾸므로, 후속 테스트를 별도 PR로 만들던 계획을 정리한다. Claude는 검수된 Sol fc752ad7을 #4에 merge해 신규 공식 fixture 테스트 3개·두 테스트 기반 false 보완·기존 보고 이력을 보존하고, 현재 main/c76의 최신 상태 문서를 유지한다. 이후 scan 수정과 새 회귀 검증을 같은 PR #11에서 완료한다. Sol의 원래 브랜치는 쓰지 않는다.

새 공식 하한 첫 페이지는 키 변형·DB 비밀값 검사 후 fixture와 provenance로 추가할 수 있다. 실제 API를 테스트/CI에서 호출하지 않는다. 월 걸침·목표일 뒤 마감·미래 시작·raw 1,001 중 목표 1·목표 밖 malformed/중복·legacy 동일 기간·crash/restart·세대 혼합·완료 재실행 0 HTTP를 검증한다. 실제 전체 적재 재실행은 새 코드·CI·두 독립 리뷰 후 별도로 배정한다.
