# 최초 적재 수정 독립안 대조 · codex

Claude·Sol의 완료된 독립안을 읽었다. 공통인 전체 페이지 scan, raw 완결성 검사와 목표 시작일 범위 반영 분리, legacy 완료 기록 보존·새 전략에서 미사용, additive V4와 M2 V5 이동을 수용한다. 실제 조회 조건은 agy의 제한된 probe 결과에 종속된다. 종료일 생략에 숨은 서버 상한이 있으면 이 안을 완료 방법으로 채택하지 않는다.

## 구현 전 고칠 경계

1. **페이지 세대는 반드시 분리한다.** Claude안의 같은 기간·전략에서 페이지별 최신 성공을 찾는 방식은 명시적 restart가 중간에 실패한 뒤 예전 세대 페이지와 섞일 수 있다. Sol안처럼 scan generation을 저장하고, 새 슬롯의 재개는 같은 세대의 연속 완료 페이지만 사용한다. restart-pages는 새 세대다. 같은 totalCount인 두 세대도 섞지 않는 회귀 사례가 필요하다. 완료 scan은 자기 행의 raw/선택 스냅숏과 집계만 재사용한다.
2. **구현되지 않은 옵션을 새로 만들지 않는다.** probe로 검증된 상위집합을 받는 한 가지 전략만 구현한다. 임의 2027년·미래 상한, 월별 요청 보정, 대체 공개 AJAX를 추가하지 않는다. 기존 공식 497행 fixture에 2050년 마감과 2027년 시작 행이 있으므로 종료일·시작일을 혼동하면 안 된다.
3. **선택 행도 단일 파싱 결과에서 만든다.** 모든 raw 행의 식별자·날짜·중복 검증을 마친 후 불변 ParsedPage의 범위 내 부분집합을 기존 upsert로 넘긴다. counts의 raw/선택 의미와 체크포인트가 저장하는 두 집합을 계약·ERD·runbook에서 일치시킨다.
4. **legacy 보존·zero target 사례를 고정한다.** 기존 COMPLETE 37월과 같은 기간으로 새 전략을 실행해도 HTTP를 건너뛰지 않는다. raw 첫 페이지가 모두 범위 밖이어도 원격 total을 다 읽고, raw 중복·총수 변경·불완전 페이지에서 기존 공고 변경이 0이어야 한다. 원격 0과 raw 비0/선택0을 구분한다.
5. **실측 뒤 다시 판정한다.** 새 전략의 raw/목표 수와 DB 기간 건수·월 걸침·진행·미래 시작 제외를 대조하고 재실행 0 HTTP를 확인한다. 22,733 부분 적재를 삭제하거나 새 원격 수신 수와 섞어 쓰지 않는다. 원천의 같은 총수 내 교체까지 스냅숏 일관성을 보장한다는 문구도 쓰지 않는다.

실제 구현자는 #4 작성자 Claude 한 명으로 유지한다. 아직 실제 API 조회 계약 검증 중이므로 이 기록만으로 구현 시작이나 병합을 승인하지 않는다.
