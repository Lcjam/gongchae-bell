# 4단계 · 2주 개발 계획 (확정 방향)

> 2026-11-08 · 사용자가 확정한 내용: **공공기관 채용을 한눈에 비교하는 웹** (부트텐트 같은 비교 사이트를 공공기관 채용으로) · **Thymeleaf 서버 렌더링** · 2주
> 근거: [03-feasibility.md](03-feasibility.md) (API와 기술 실현 가능성 검증 완료)

## 한 줄 정의

공공기관 채용공고를 API로 자동 수집해서 **직무, 지역, 신입 여부로 비교**하고, **마감 임박 공고**와 **기관별 채용 이력**을 보여 주는 웹이다. 공식 사이트인 잡알리오에 없는 가치는 기관별 1년 이력과 통계, 신입·IT 공고 바로 보기, 마감 임박 모음이다.

## 2주 범위

### 만드는 것 (페이지)
| 경로 | 내용 |
|---|---|
| `/` | 마감 임박(D-3 이내), 오늘 새로 올라온 공고, 직무 분야 바로가기 |
| `/jobs` | 목록: 필터(NCS 직무, 지역, 고용형태, 신입/경력, 진행/마감), 정렬(마감일, 등록일), 제목 키워드, 페이징 |
| `/jobs/{sn}` | 상세: 자격, 우대, 전형 단계, 첨부(상세 API), 원문 링크 (기관 첫 화면이면 잡알리오 링크로 대체) |
| `/institutions/{code}` | 기관: 최근 1년 공고 수, 채용 인원 합계, 공고 이력 |
| `sitemap.xml`, `robots.txt`, 메타 태그 | 검색엔진 등록용 |

### 2주 안에는 안 하는 것
로그인, 관심 공고, 마감 알림(3주차 후보) · 후기와 댓글 · React · Redis · Spring Batch · 이메일

## 기술 스택
- Java 21 (또는 25) · **Spring Boot 4.1.x** · Spring MVC + **Thymeleaf** · Spring Data JPA (동적 필터는 Specification) · `RestClient`
- PostgreSQL 17 · Flyway · Testcontainers
- 재시도는 Spring Framework 7 내장 `@Retryable`로 한다 (Resilience4j 없이)
- Actuator + Micrometer(Prometheus) · Grafana · Healthchecks.io · 외부 업타임 감시
- Docker Compose · Caddy (자동 HTTPS) · GitHub Actions (`ubuntu-24.04-arm`) · GHCR
- CSS는 가벼운 프레임워크 하나 (Bootstrap 또는 Pico.css)

## 데이터 설계 (초안)
| 테이블 | 핵심 컬럼 | 용도 |
|---|---|---|
| `job_posting` | `sn`(PK, `recrutPblntSn`), 제목, 기관코드, 시작일, 마감일, 채용구분, 고용형태, NCS, 지역, 인원, `src_url`, `content_hash`, `first_seen_at`, `last_changed_at`, `status` | 공고 본체 |
| `posting_change` | `sn`, `changed_at`, 바뀐 필드 | 변경 이력 ("수정된 공고" 표시와 운영 기록) |
| `institution` | 기관코드, 기관명 | 기관 페이지 |
| `collect_run` | 시작, 종료, 결과, 받은 건수, 신규, 변경, 오류 | **수집 신뢰성 증거** (운영 대시보드와 포트폴리오) |

- 코드표 PDF는 파싱하지 않는다. API가 코드와 이름을 함께 주므로(`ncsCdNmLst`, `workRgnNmLst`, `hireTypeNmLst`, `recrutSeNm`) 필터 선택지는 수집한 데이터에서 만든다.

## 수집 설계 (검증된 수치 기준)
- **최초 적재**: 최근 1년 11,784건. 1,000건씩 호출 12번.
- **정기 수집**: 1시간마다 `ongoingYn=Y`로 1회 호출(현재 504건). 공고번호 기준 upsert → 해시가 다르면 변경 이력을 남긴다 → 목록에서 빠진 공고는 마감 처리한다.
- **상세 조회**: 새 공고만 부른다 (하루 약 30회).
- **정제**: 깨진 문자 표시, 기관 첫 화면 링크는 `https://job.alio.go.kr/recruitview.do?idx={sn}`로 대체 (동작 확인함).
- **실패 처리**: 타임아웃과 `@Retryable`, `collect_run`에 결과 기록, 수집이 끝나면 Healthchecks.io로 신호를 보낸다.
- **호출량**: 하루 약 54회. 개발계정 한도 1,000회의 5%다.

## 일정

### 1주차: 제품 완성과 첫 배포
| 일차 | 할 일 | 완료 기준 |
|---|---|---|
| 1 | 프로젝트 생성, 로컬 Compose(PostgreSQL), Flyway 스키마, API 클라이언트 + 실제 응답으로 만든 테스트 | 테스트 통과 |
| 2 | 수집기(upsert, 해시, 변경 이력, `collect_run`) + 1년치 최초 적재 | DB에 약 1.2만 건 |
| 3 | 정기 수집 스케줄 + 새 공고 상세 조회 + 정제 + 재시도 | 1시간 주기로 동작 |
| 4 | `/jobs` 목록 (필터, 정렬, 페이징, 키워드) + 인덱스 | 필터 조합이 동작 |
| 5 | `/jobs/{sn}` 상세 + `/` 홈 (마감 임박, 신규) | |
| 6 | `/institutions/{code}` 기관 통계 + SEO (sitemap, 메타 태그) | |
| 7 | 서버에 첫 배포 (Compose 수동) + 도메인 + HTTPS + 구글 서치콘솔과 네이버 서치어드바이저 등록 | 외부에서 접속 가능 |

### 2주차: 운영 기반 (포트폴리오의 핵심)
| 일차 | 할 일 | 완료 기준 |
|---|---|---|
| 8 | GitHub Actions: 테스트 → ARM64 이미지 → GHCR → 배포 자동화 | push하면 배포 |
| 9 | 무중단 배포 (blue/green, readiness, graceful shutdown) + 실패 시 자동 롤백 | 배포 중 외부 연속 요청 실패 0을 실측 |
| 10 | 관측: Grafana에 HTTP p95와 오류율, 수집 결과, 마지막 성공 시각 + 디스코드 운영 알림 + Healthchecks.io + 외부 업타임 감시 | 대시보드와 알림 동작 |
| 11 | 목록 쿼리 실행계획 점검과 인덱스 + 간단한 부하 측정 기준선 (k6) | 전후 수치 기록 |
| 12 | 백업 자동화 (`pg_dump` → Object Storage + OCI 밖 사본) + **복원 리허설 시간 실측** + 기본 보안 (Actuator와 DB 비공개) | 복원 시간 기록 |
| 13 | 장애 훈련 1~2개 (수집 중단, API 오류 주입) + 회고 문서 + README (아키텍처, 운영 기록) | `docs/incidents/` 첫 문서 |
| 14 | 예비일 | |

## 2주 뒤
- **최소 1~2개월은 그대로 운영**하면서 배포 이력, 장애와 훈련 회고, 실제 방문 지표를 기록한다. 이력서 수치는 이 기간의 실측만 쓴다.
- 3주차 후보: 카카오나 구글 로그인(OAuth2) + 관심 공고 + 마감 알림
- 초기 사용자: 취업 스터디와 커뮤니티에 공유한다. 검색 유입은 색인까지 몇 주 걸리고 보장되지 않는다.

## 리스크
| 리스크 | 대응 |
|---|---|
| 같은 API를 쓴 공개 프로젝트가 여럿 있다 | 기관 이력과 통계, 운영 기록으로 차별화한다 |
| 화면 작업이 늘어나 일정이 밀린다 | 디자인은 CSS 프레임워크 기본값으로. 6일차까지 못 끝내면 기관 페이지를 2주차 예비일로 넘긴다 |
| 공식 API의 일시 장애 | 재시도와 수집 기록. 그래도 안 되면 공개 JSON 경로로 대체 수집 |
| 검색 유입이 생기지 않는다 | 운영 경험은 배포, 백업, 수집 신뢰성만으로도 기록할 수 있다 |
