2026-11-16. M1 PR11은 최종49ea5cf/CI43714836398와 두 독립 검수 후 main에 병합됐다(merge000dce555e9eb69ef3184dd5f80aa1d499a1f602). #6 구독·보안·확인 경로를 선행 구현하고, #7 매칭·비동기 발송은 #6 검수·병합 뒤에 시작한다. #6 단독 작성자는 Claude다. root는 구현하지 않고 결과를 검수한다.

## 채택 계약

기존 PRD/ADR와 이 폴더06~08을 유지한다. 09는10·11의 모순 지적에 따라12로 정정됐다. **12를13의 네 가지 보완과 함께 수용한다.** 13은 root도 코드 경합 순서와 요구사항을 대조해 수용한 필수 구현 조건이며, 12의 충돌 문구보다 우선한다.

1. EMAIL_CONFIRM의 SENT는 PENDING을 유지한다. 유효한 목적별 확인 POST가 현재 hash·24시간·미사용 조건을 원자적으로 검사/소비하고 confirmed_at을 쓸 때만 ACTIVE다. 실제로 도착했다면 발송 결과가 unknown이어도 유효 확인 POST를 허용한다.
2. unknown 시도 뒤에는 item 보존과 발송 자격을 분리한다. 현재 구독·종류·조건·공고 유효성의 대상 집합이 달라지면 hash가 같아도 새 예약/HTTP 없이 UNCERTAIN으로 종결한다. 보존 item은 중복 방지용이며 전송 허가가 아니다. hash는 실제 공급자 요청 전체의 결정적 payload에 대해 계산한다. 원문/암호문 본문·토큰은 저장하지 않는다.
3. 외부 A가 부모 SHARE 아래 R을 부르기 전에는 자식 DML/자동 flush/잠금이 없어야 한다. R이 별도 연결에서 펜싱·상한·시도 행·키/hash를 함께 커밋한 뒤 A가 notification을 잠그고 claim/상태/예약/자격/마감을 다시 검사한다. 그 잠금을 한 HTTP와 결과 커밋까지 유지한다. 결과·회수·종결은 notification→attempt/item 순서이며 부모가 필요한 경로는 subscription부터다. R의 최신 필드를 오래된 엔티티 flush로 덮어쓰지 않는다.
4. 동기25초는 신청·DB/풀/잠금·R·HTTP·대기·정리까지 고려한 예산이다. 단조 시계로 R 뒤 HTTP 직전에도 다시 검사하고 정리 몫을 남긴다. 예약 뒤 전송하지 못해도 환불하지 않으며 durable 기록을 보존한다. GC/OS/DB 장애까지 물리적25초 응답을 보장한다고 과장하지 않는다. 구현에서 대기/획득 timeout과 마감 동작을 검증한다. 최대3시도와 비동기23시간 경계는12·13대로다.

5번째 notification_attempt는 시도별 durable 예약과 과거 unknown 보존을 위한 최소 추가로 수용한다. 범용400/422 누적 비활성화는 철회하며 명확한 수신자 귀책을 식별할 공식 응답이 현재 없음을 기록한다. Discord404 즉시 비활성화/401 작업 실패는 유지한다. ‘Resend 실패 응답은 캐시하지 않는다’는 주장은 근거가 없어 채택하지 않는다.

## 개인정보와 실사용 준비

[Sol 공식 출처 검토](../2026-11-16-m2-privacy/sol-source-review.md)를 구현과 고지의 근거로 쓴다. root도 법 제28조의8의 서로 다른 이전 근거와 Resend retention 문서를 직접 확인했다. 기존 동의·14세·상태별 파기·해지 대장·출처/보유 고지를 코드/문서에 반영하며, 실제 담당 연락처는 런타임 필수 설정으로 취급한다. 임의 이름·이메일·미확인 국가/기간으로 채우지 않는다.

IP/대상 HMAC 만료행의 실제 정리 주기·최장 잔존, 해지 대장 보유/정리와 백업 보유·복원 제한의 일치는 #6 구현자가 구체안을 기록하고 리뷰받아 닫는다. 원문 토큰이나 새 추적/반송 기능을 추가해 해결하지 않는다. 대역 구현 전체를 법적 미확정 때문에 중단하지 않는다. 동시에 실제 개인정보 수집/발송 전에 공개 고지의 실제 값, 국외 처리 근거·provider/OCI Tokyo 위치·DPA/보유/추적 off를 확인하는 게이트를 생략하지 않는다. 앱 DB 삭제와 공급자/백업/Discord 게시물의 잔존을 구분한다.

## 구현·검수 범위

#6는 격리 워크트리에서 V5, 구독 생명주기/목적별 토큰, 엄격한 입력·Origin/남용 방지, 제한 동기 발송과 시도 감사, Discord URL/주소 검사·암호화, 관리/복구/조건 수정/해지, 고지/처리방침, 파기/대장을 완성한다. 실제 외부 수집·Resend/Discord 발송·서버/DNS 변경은 이 개발 과제에 넣지 않는다. 테스트는 provider 대역과 격리 PostgreSQL을 쓰며 기존 수집 설정은 false로 고정한다.

작성자는 관련 ADR/ERD/routes/상태표·실행 설정 이름을 실제 구현과 맞추고 자체 검증·CI·비밀값 검사를 마친 불변 커밋과 draft PR을 제출한다. root와 구현하지 않은 별도 리뷰어가 검수한다. #7 기능과 공개 배포/운영까지 완료됐다고 표시하지 않는다. 구체 구현에서 추가 결함이 발견되면 담당 작성자가 수정하며, root가 대신 구현하지 않는다.
