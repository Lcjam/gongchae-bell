# M2 개인정보 고지 출처 검토 · sol

2026-11-16. `CLAUDE.md`, PRD FR-A6/§6, ADR-0007/0009/0010/0012/0013/0014와 M2 readiness 06~08을 대조했다. **설계 계약과 공식 문서의 읽기 조사**이며 #6 코드·실제 계정 설정·파기 동작·법적 적합성의 최종 검증은 아니다. 사용자 개인정보·계정·env·DB를 읽지 않았고 실제 전송·가입·메일·OCI 조작은 하지 않았다.

## 한국어 고지에 필요한 항목

현재 국가법령정보센터에서 확인한 법/시행령은 2026-09-11 시행본이다. 아래는 이 앱에 적용할 항목의 점검이며 법률자문을 대신하지 않는다.

| 경계 | #6 화면·처리방침에 필요한 내용 |
|---|---|
| 신청 동의 | 목적, 수집 항목, 보유·이용 기간, 거부권과 불이익을 신청 전에 표시한다. 거부 시 알림만 신청할 수 없고 공고 조회는 가능하다. 개인정보 수집·이용과 별도 동의가 필요한 사항을 구분하고 미리 체크하지 않는다. 동의 없이 처리할 항목은 법적 근거와 함께 구분한다. [법 제15조②](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334879), [제22조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335517) |

## 앱 데이터·보유 고지 경계

아래 기간은 **설계에서 수용한 값**이며 실운영에서 파기가 완료된 측정값은 아니다. 주기 실행의 최대 지연까지 포함한 실제 파기 시점을 #6/#7과 맞춰야 한다.

| 데이터·목적 | 수용 계약 / 미확정 사항 |
|---|---|
| 이메일·관심 조건·알림 종류 / 구독·매칭 | PENDING은 확인 토큰 24시간 만료 시 삭제, ACTIVE는 해지까지, DISABLED는 비활성화 30일 뒤 삭제. 해지 때 이메일과 연결된 발송 데이터까지 삭제한다. DISABLED 보유 중 발송을 계속한다는 뜻은 아니다. |
| Discord 목적지 / 채널 알림 | 토큰을 포함하는 웹훅 URL은 AES-GCM 암호화 저장, 정규화 목적지 HMAC을 관리/중복판별에 사용한다. 암호화가 개인정보·비밀정보 처리 자체를 없애지는 않는다. 관리 링크는 채널에 보내지 않는다. 해지 시 관련 목적지/조건/토큰 자료도 파기해야 한다. |
| IP·목적지 HMAC 카운터 / 남용 방지 | IP/이메일/웹훅 원문 대신 HMAC을 저장한다. 창 크기(10분·1시간)는 **행 보유 상한과 같지 않다**. 만료 행 정리의 구체 주기/최장 잔존시간은 읽은 계약에 숫자가 없어 미확정이다. 목적·처리 근거·확정 TTL을 고지하고 “IP는 전혀 처리하지 않음”이라 쓰지 않는다. 앱·프록시 로그의 raw IP 보유도 별도 점검해야 한다. |
| 확인/관리 토큰 hash·동의 버전/동의·확인 시각 | 토큰 목적·만료/일회 사용·구독 생존기간을 구분한다. DB hash만으로 처리한다고 해서 이메일 공급자가 토큰을 못 본다는 뜻은 아니다. 확인/관리/해지 링크는 **메일 본문의 일부로 공급자에게 전송**된다. 해지 후 동의 증빙을 계속 보관하려면 항목·근거·기간을 별도로 확정해야 하며 무기한 보존을 임의로 추가하지 않는다. |
| 발송/동기 확인 시도·결과 | 완료 기록 30일, 중복키는 구독이 살아 있는 동안이라는 계약이다. 고정 결과 코드 위주로 남기고 토큰/본문을 새로 DB에 저장하지 않는다. 동기 확인은 비동기 재발송/회수 대상이 아니다. |
| 백업 / 장애 복구 | DB·대장은 OCI 저장소와 NAS·PC 사본에 암호화·접근제한, 설계상 보관 14일. **법이 백업에 14일의 파기 유예를 자동 허용한다는 근거는 아니다.** 각 사본의 실제 prune/삭제와 복원 전 해지 재적용·발송 중단이 필요하다. `keep-daily 14` 스냅샷 설정만으로 모든 사본이 14일 이내 사라진다고 단정하지 않는다. NAS/PC의 실제 국가·잔존/정리 실행은 미확인이다. [법 제21조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900078981) |
| erasure UUID·해지 시각 / 복원 후 재발송 방지 | 06~08의 수용 경계대로 **“UUID는 개인정보 아님” 문구를 쓰지 않는다.** 운영자가 보유하는 백업/구독 자료와 연결 가능성을 고려한다. 대장 보유기간·정리 조건은 미확정이며 임의 14일/무기한으로 쓰지 않는다. 비정상·잘린 줄은 fail-closed, VM 유실 시 마지막 백업 이후 대장 유실/재발송 가능성도 고지 경계에 남긴다. [법 제2조의 결합·가명정보 기준](https://www.law.go.kr/LSW/LsiJoLinkP.do?docType=JO&joNo=002800004&languageType=KO&lsNm=개인정보%20보호법&paras=1) |

배포 예정지가 이전 콘솔에서 관측된 **OCI Tokyo**로 유지되면 앱/DB의 일본 처리도 방침 대상이다. 국외 처리를 Resend 미국만으로 축소하면 안 된다. 아직 공채벨 배포·Object Storage/NAS의 실제 개인정보 저장을 검증한 결과는 아니며, 호스팅 법인/계약·이전 근거·각 저장 위치를 실제 배치와 맞춰 확정해야 한다.

## #6의 필수 체크

1. 신청 전 한국어 고지·필수 동의·14세 확인을 서버에서도 검사하고 실제 고지 버전/동의·활성화 시각을 저장한다. 방침은 로그인/관리 토큰 없이 접근 가능해야 한다. 거부자의 공고 조회는 유지한다.
2. 운영 담당 성명/부서·전화 등 연락처, 시행일/버전, 실제 수탁자/재수탁·이전 근거/국가/항목/시기/방법/연락처/목적/기간/거부 절차를 **실운영 시작 전 필수 설정·검수 조건**으로 둔다. 자리표시자나 공급자 미확인 기간을 임의 수치로 채우지 않는다. 별도 이전 동의 경로를 선택하면 수집·이용 동의와 분리한다.
3. 구독/토큰/시도 기록의 삭제 cascade와 cleanup, IP·목적지 HMAC TTL, 대장 보유·정리 조건을 고지값과 맞춘다. 법적 보존 의무가 확정되지 않은 데이터를 증빙 명목으로 임의 장기 보존하지 않는다. 백업·공급자 사본·외부 게시물은 앱 DB 파기와 구분한다.
4. 이메일·웹훅·원문 토큰이 앱/프록시/HTTP 예외·오류 화면/지표 label에 노출되지 않는지 확인한다. hash/HMAC을 익명정보로 단정하지 않는다. 관리 화면 `no-referrer`/`no-store`, 목적별 capability 경계를 유지한다.
