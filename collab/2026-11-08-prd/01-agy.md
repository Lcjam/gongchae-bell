## 1. 문제 정의 (Problem Definition)

### 구직자(사용자) 관점의 문제
- **과도한 탐색 비용 및 필터링 한계**: 공공기관 채용정보 포털(잡알리오)은 수많은 공고가 등록되지만, 전산/IT 등 특정 직무를 준비하는 신입 구직자가 '정보통신 + 신입 + 정규직' 등의 세부 조건을 빠르게 조합하여 비교하기 어렵습니다.
- **마감 임박 공고 파악 불편**: 접수 마감이 임박한(D-3 이내) 공고를 한눈에 모아보지 못해 중요한 지원 기회를 놓치기 쉽습니다.
- **기관별 과거 채용 맥락 부재**: 특정 공공기관이 연간 몇 명을 채용하는지, 최근 1년간 어떤 직무 공고를 냈는지 기관 단위의 누적 이력과 통계를 제공하지 않아 채용 규모를 예측하기 어렵습니다.
- **저품질 링크로 인한 사용자 이탈**: 공식 API 제공 데이터 중 약 20%(실측 101/504건)는 개별 공고 상세가 아닌 '기관 대표 홈페이지'로 연결되어 구직자가 해당 사이트에서 다시 공고를 찾아 헤매야 합니다.

### 개발자(포트폴리오) 관점의 문제
- 단순 CRUD나 가상의 모의 프로젝트는 신입 채용 시장에서 변별력을 잃었습니다.
- 실제 외부 공공 API를 안정적으로 연동·정제하고, 단일 서버(OCI Ampere A1) 제약 속에서 **무중단 배포, 관측 체계, 장애 격리, 백업·복구 리허설**을 수행하며 실측 수치와 운영 사건을 입증할 수 있는 실제 운영 서비스가 필요합니다.

## 2. 대상 사용자 및 페르소나 (Target Personas)

### 페르소나 1: 공공기관 IT/전산직 신입 취준생 "김민수 (26세)"
- **상황**: 공기업·공공기관 전산직 취업을 준비 중이며, 매일 잡알리오와 취업 카페를 수동으로 순회함.
- **고통(Pain Point)**: 정보통신 직무 공고가 전체 공고 중 소수(최근 1년 기준 약 8%)에 불과하여 필터링 없이 목록을 뒤지는 데 많은 시간을 낭비함. 마감 직전에야 공고를 발견해 서류 준비가 촉박함.
- **니즈**: '신입 + IT/정보통신 + 정규직' 공고를 즉시 모아보고, 마감 D-3 이내 공고를 최우선으로 확인하고 싶음. 지원 전 해당 기관의 1년간 채용 빈도와 인원을 파악하고 싶음.

### 페르소나 2: 지역 이전 공공기관을 탐색하는 일반 취준생 "이지은 (28세)"
- **상황**: 혁신도시 이전 공공기관 및 특정 지역(대구, 나주 등) 공기업을 중심으로 구직 활동 중.
- **고통(Pain Point)**: 모바일이나 웹에서 검색 시 외부 링크가 기관 첫 화면으로 튕기거나 인코딩이 깨진 공고를 자주 접함.
- **니즈**: 지역 및 고용형태별로 신뢰할 수 있는 필터 검색을 이용하고, 깨진 링크 없이 바로 정확한 공고 본문(또는 잡알리오 상세 페이지)으로 이동하고 싶음.

| **메모리 점유율** | **6GB 이하 / 12GB** | `docker stats` 실측 (상시 및 배포 순간) | OCI Ampere A1 (12GB) OOM Killer 방지 |

## 4. 범위 (Scope - 2주 MVP 기준)

### (1) 포함 범위 (In-Scope)
- **공공 API 데이터 수집 및 정제 파이프라인**:
  - 최근 1년치 공고(약 1.2만 건) 최초 적재 배치.
  - 1시간 주기 진행 중 공고(현재 504건) 수집 및 해시 기반 변경 감지/마감 처리.
  - 새 공고에 대한 상세 API(`/detail`) 호출 및 전형 단계/첨부파일 적재.
  - 기관 첫 화면 링크 대체 및 인코딩 깨짐 처리.
  - 수집 실행 이력(`collect_run`) 저장 및 Healthchecks.io 완료 핑 발송.
- **웹 페이지 (Thymeleaf 서버 사이드 렌더링 + 경량 CSS)**:
  - `/`: 홈 (마감 임박 D-3 공고, 오늘 신규 공고, 주요 직무 바로가기).
  - `/jobs`: 공고 목록 (다중 필터, 제목 키워드 검색, 마감일/등록일 정렬, 페이징).
  - `/jobs/{sn}`: 공고 상세 (자격 요건, 전형 일정, 첨부파일, 대체/원문 지원 링크).
  - `/institutions/{code}`: 기관별 상세 (최근 1년 채용 공고 수, 총 채용 인원, 공고 타임라인).
  - SEO: `sitemap.xml`, `robots.txt`, 동적 메타 태그 (Open Graph).
- **인프라 및 운영 자동화**:
  - Docker Compose (Caddy + Spring Boot Blue/Green 2개 + PostgreSQL 17 + 관측 스택).
  - GitHub Actions CI/CD (테스트, ARM64 도커 빌드, GHCR 푸시, 자동 롤백 포함 무중단 배포).
  - Prometheus + Grafana 대시보드 (HTTP p95, 오류율, JVM 힙, 수집 지표).
  - OCI Object Storage 일일 DB 덤프 자동화 및 복원 리허설 1회 수행.

### (2) 제외 범위 (Out-of-Scope - 2주 MVP 이후 백로그)
- 회원가입, 로그인(OAuth2) 및 개인화 기능 (관심 공고 북마크 등).
- 개인별/그룹별 마감 알림 발송 (Discord 개인 봇, 카카오톡, 이메일).
- 사용자 댓글, 리뷰, 커뮤니티 게시판.
- React/Vue 등 프론트엔드 SPA 프레임워크 도입 (Thymeleaf로 단일화).
- Redis 캐시 서버 도입 (메모리 절약 및 PostgreSQL 인덱스로 충분).
- Spring Batch 프레임워크 도입 (Spring Framework `@Scheduled` + `@Retryable`로 경량화).
- OCI Email Delivery 연동 (Always Free 한도 0 이슈로 완전 배제).

## 5. 기능 요구사항 (Functional Requirements)

### (1) 데이터 수집 및 가공 모듈
- **`FR-COL-01` [Must] 정기 공고 수집 스케줄러**
  - **설명**: 1시간 주기로 `apis.data.go.kr/1051000/recruitment/list` API(`ongoingYn=Y`)를 호출하여 진행 중 공고를 수집한다.
  - **수용 기준**:
    - 한 번의 수집 시 `numOfRows=1000` 파라미터로 1회 호출하여 전량을 수집한다.
    - 일일 수집 API 호출량은 정기 24회 + 상세조회 30회 내외로 일일 한도(1,000회)의 10% 이하를 유지해야 한다.
    - 일시적 네트워크 오류 시 `@Retryable`로 최대 3회 지수 백오프 재시도한다.
- **`FR-COL-02` [Must] 공고 변경 감지 및 자동 마감**
  - **설명**: 수집된 공고의 내용 해시(SHA-256)를 기존 레코드와 비교하여 변경 사항을 감지한다.
  - **수용 기준**:
    - `recrutPblntSn`이 일치하고 내용 해시가 변경된 경우 `posting_change` 테이블에 변경 일시와 변경 내용을 기록하고 공고 본체를 갱신한다.
    - API 응답 목록에서 누락된 기존 진행 공고는 상태를 '마감(CLOSED)'으로 전환한다.
- **`FR-COL-03` [Must] 신규 공고 상세 정보 적재**
  - **설명**: 최초 수집된 신규 공고에 한해 `/detail` API를 호출한다.
  - **수용 기준**:
    - 상세 응답에 포함된 전형 단계(`steps`)와 첨부파일 목록(`files`)을 정규화하여 DB에 저장한다.
    - 이미 상세 정보를 가져온 기존 공고에 대해서는 중복 호출하지 않는다.
- **`FR-COL-04` [Must] 원문 링크 정제 및 텍스트 보정**
  - **설명**: API의 저품질 데이터를 표출 전 자동으로 정제한다.
  - **수용 기준**:
    - 원문 링크(`srcUrl`)가 기관 첫 화면 도메인인 경우 `https://job.alio.go.kr/recruitview.do?idx={sn}`로 대체한다.
    - 인코딩 깨짐 문자가 감지되면 제거하거나 정제하여 UI 깨짐을 방지한다.
- **`FR-COL-05` [Must] 수집 실행 이력 기록 및 헬스 신호**
  - **설명**: 수집 파이프라인의 실행 결과를 감사 테이블에 저장하고 외부 헬스체크에 보고한다.
  - **수용 기준**:
    - 실행 시작/종료 시각, 소요 시간, 결과 상태(SUCCESS/FAIL), 수집 건수, 신규 건수, 변경 건수, 에러 메시지를 `collect_run`에 기록한다.
    - 수집 성공 시 Healthchecks.io로 ping을 발송한다.
- **`FR-COL-06` [Must] 1년치 초기 데이터 적재 (Seed Runner)**
  - **설명**: 서비스 초기 구동 시 최근 1년치 공고(약 1.2만 건)를 일괄 적재한다.
  - **수용 기준**:
    - 페이징(1,000건 단위 12회) 호출을 통해 중복 없이 `job_posting`에 적재되어야 한다.

### (2) 사용자 웹 화면 (Thymeleaf)
- **`FR-VIEW-01` [Must] 홈 화면 (`/`)**
  - **수용 기준**:
    - 마감 임박 공고(D-3 이내) 목록을 카드 형태로 최대 6~8건 표출한다.
    - 오늘 새로 등록된 신규 공고 목록을 표출한다.
    - 주요 직무(정보통신, 경영/회계, 기술 등) 필터 링크 바로가기를 제공한다.
- **`FR-VIEW-02` [Must] 공고 목록 및 검색 (`/jobs`)**
  - **수용 기준**:
    - NCS 직무 코드, 근무 지역, 고용 형태(정규직/비정규직), 채용 구분(신입/경력), 진행 여부(진행중/마감) 다중 필터를 지원한다.
    - 제목 키워드 검색을 지원한다.
    - 정렬 기준(마감일 임박순, 등록일 최신순) 변경이 가능해야 한다.
    - 한 페이지당 15~20건 단위 페이징 처리를 지원한다.
- **`FR-VIEW-03` [Must] 공고 상세 화면 (`/jobs/{sn}`)**
  - **수용 기준**:
    - 공고 제목, 기관명, 접수 시작/마감일, D-day, 채용 인원, NCS 분야, 근무 지역을 표시한다.
    - 전형 단계(서류, 필기, 면접 등) 타임라인과 첨부파일 다운로드 링크를 제공한다.
    - 정제된 유효 지원 링크 버튼을 제공한다.
    - 해당 기관의 상세 페이지(`/institutions/{code}`)로 이동하는 링크를 제공한다.
- **`FR-VIEW-04` [Should] 기관별 채용 이력 화면 (`/institutions/{code}`)**
  - **수용 기준**:
    - 기관명, 기관 코드, 최근 1년 총 공고 건수, 총 채용 인원 합계 통계 카드를 상단에 노출한다.
    - 해당 기관이 과거 등록한 공고 목록을 최신순으로 정렬하여 표시한다.
- **`FR-SEO-01` [Should] SEO 및 검색엔진 메타데이터**
  - **수용 기준**:
    - `/sitemap.xml` 및 `/robots.txt`를 동적으로 서빙한다.
    - 공고 상세 및 기관 페이지에 Open Graph 태그(`og:title`, `og:description`, `og:url`)를 렌더링한다.

## 6. 비기능 요구사항 (Non-Functional Requirements)

### (1) 성능 (Performance)
- **`NFR-PERF-01` 웹 응답 시간**: 목록(`/jobs`) 및 상세(`/jobs/{sn}`) 화면의 p95 서버 응답 시간은 300ms 이하여야 한다.
- **`NFR-PERF-02` DB 쿼리 효율**: 1.2만 건 데이터 기준, 필터 검색 쿼리의 인덱스 스캔 실행 시간은 50ms 이하여야 한다 (`recrut_se`, `ncs_cd_lst`, `pbanc_end_ymd` 복합/단일 인덱스 적용).

### (2) 가용성 및 배포 (Availability & Deployability)
- **`NFR-AVAIL-01` 무중단 배포 (Zero-Downtime)**: Blue/Green 배포 시 Caddy의 리버스 프록시 upstream 전환과 Spring Boot의 graceful shutdown(20초)을 적용하여, 배포 중 인입되는 연속 HTTP 요청의 유실율(5xx 에러) 0건을 달성해야 한다.
- **`NFR-AVAIL-02` 자동 롤백**: 신규 컨테이너 배포 후 Actuator Health Check 실패 시 기존 버전으로 자동 롤백되어야 한다.
- **`NFR-AVAIL-03` 상시 가동률**: 월간 가동률 99.9% 이상을 유지해야 한다 (Healthchecks.io 외부 감시 기준).

### (3) 보안 (Security)
- **`NFR-SEC-01` 전송 구간 암호화**: Caddy를 통해 HTTPS(TLS 1.3)를 강제 적용하며, HTTP 요청은 HTTPS로 자동 리다이렉트한다.
- **`NFR-SEC-02` 비밀값 격리**: 공공데이터 API 키, DB 비밀번호 등은 코드나 커밋에 일절 포함하지 않고 `.env` 및 GitHub Secrets로만 관리한다.
- **`NFR-SEC-03` 엔드포인트 접근 제어**: Actuator의 민감 엔드포인트(`/env`, `/heapdump` 등)는 외부 인터넷에 노출하지 않고 로컬호스트 또는 내부 컨테이너 네트워크로만 접근을 제한한다. DB(5432) 포트의 외부 바인딩을 금지한다.

### (4) 운영성 및 메모리 예산 (Operability & Budgeting)
- **`NFR-OPS-01` 메모리 예산 관리 (Memory Budgeting)**:
  - OCI Ampere A1 (12GB) 환경에서 상시 메모리 사용량을 5.5GB 이하, Blue/Green 배포 피크 시 6.5GB 이하로 통제하여 시스템 OOM Killer 발동을 원천 차단한다.
  - *예산 배분*: Spring Boot 컨테이너당 Max Heap 512~768MB (RSS 각 1.2GB) / PostgreSQL shared_buffers 512MB (RSS 1.2GB) / Prometheus+Grafana (0.8GB) / Caddy+OS (0.8GB).
- **`NFR-OPS-02` 백업 및 복구 체계**:
  - 매일 새벽 4시 `pg_dump`를 수행하여 OCI Object Storage에 자동 업로드하고 14일 경과 백업본을 자동 정리한다.
  - 스프린트 2 기간 중 1회 이상 복원 리허설을 수행하고 실측 RTO를 문서화한다.

## 7. 2주 MVP 완료 기준 (Definition of Done)

1. **데이터 파이프라인**: 1년치 공고 적재 완료 및 시간당 1회 정기 수집 배치가 중단 없이 동작하며 `collect_run`에 성공 이력이 남는다.
2. **핵심 웹 기능**: `/`, `/jobs` (다중 필터/검색), `/jobs/{sn}` (상세 및 링크 정제), `/institutions/{code}` 페이지가 정상 렌더링된다.
3. **CI/CD 파이프라인**: GitHub Actions에서 테스트 통과 ➡️ ARM64 컨테이너 빌드 ➡️ GHCR 푸시 ➡️ OCI 서버 Blue/Green 무중단 배포가 자동화된다.
4. **무중단 실측**: 배포 진행 중 외부 루프 요청 테스트에서 5xx 오류 0건을 실측하고 로그로 증명한다.
5. **모니터링 체계**: Prometheus/Grafana 대시보드에서 JVM 메모리, HTTP 응답시간, 수집 상태가 시각화되고 Healthchecks.io로 주기적 신호가 전송된다.
6. **백업 및 복구 리허설**: OCI Object Storage 일일 백업이 가동되고, `docs/ops/backup-restore.md`에 복원 리허설 실측 기록이 존재한다.
7. **CLAUDE.md 규칙 준수**: 5대 DoD 항목 충족, 비밀값 노출 0건, 모든 수치는 실측치만 사용.

## 9. 열린 질문 (사용자 결정 필요 사항)

1. **서버 사양 확인**: 현재 보유하신 Oracle Cloud 서버가 **Ampere A1 (ARM64, 2 OCPU / 12GB)** 인스턴스가 맞는지 확인이 필요합니다. (만약 AMD Micro 1GB 서버만 있다면 메모리 부족으로 아키텍처 재설계가 필요합니다.)
2. **도메인 연결 방식**: 무료 DDNS인 **DuckDNS 서브도메인**(`*.duckdns.org`)을 사용할 것인지, 아니면 별도 구입하신 **개인 커스텀 도메인**을 연결하실 계획인지 확인이 필요합니다.
3. **CSS 프레임워크 선호도**: 관리자형 대시보드나 빠른 웹 구현을 위해 **Bootstrap 5**와 클래스리스 경량 프레임워크인 **Pico.css** 중 선호하시는 도구가 있는지 결정이 필요합니다.
