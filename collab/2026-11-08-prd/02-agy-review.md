## 1. 사실 오류와 근거 없는 수치 지적

`CLAUDE.md`의 핵심 규칙은 **"수치는 실측만 쓴다. 추정은 추정이라고 표시한다. 근거 없는 목표치는 기준선 측정 후 설정으로 둔다"**입니다. 세 문서의 수치를 대조·검증한 결과는 다음과 같습니다.

### (1) agy 01 초안의 중대한 규칙 위반 (근거 없는 수치 확정)
- **가동률 99.9% 목표**: OCI Always Free 단일 VM(A1 1대)은 SLA가 제공되지 않으며, 단일 노드 아키텍처에서 2주 MVP 시점에 월간 가동률 99.9%(월 장애 43분 이내)를 보장하는 것은 **근거 없는 허구**입니다.
- **응답 시간 p95 300ms 및 쿼리 50ms**: `03-feasibility.md`에 기록된 599ms/175ms는 외부 공공 API 단일 호출 관측값일 뿐, 자체 WAS 서버 렌더링 응답시간은 아직 측정한 적이 없습니다. 실측 기준선(Baseline) 없이 300ms를 목표로 확정한 것은 위반입니다.
- **일일 수집 성공률 99% 이상**: 하루 24회 배치 중 99%는 통계적으로 연간 단위 지표이며 2주 기간에 맞지 않습니다.
- **복구 시간 RTO 15분**: 실제 복원 리허설을 돌려보지 않은 상태에서 미리 설정한 추정치입니다.
- ➡️ **조치**: agy 01의 모든 성능·가용성·신뢰도 수치 목표를 철회하고 **"Sprint 2 기준선 실측 후 설정"**으로 변경합니다.

### (2) Claude 01 초안의 미검증 전제 및 수치
- **수집 지연 임계값 2시간 설정**: "마지막 수집 성공 후 2시간이 지나면 알림(NFR)"은 직관적이나, 외부 API 야간 점검(보통 1~2시간 소요) 빈도나 네트워크 지터를 측정하지 않고 임의로 확정한 값입니다.
- **소비 호출량 10% 미만**: 설계 계산상 54회/일(5.4%)은 타당하나, 초기 적재 및 재시도·장애 훈련 호출량이 합산되지 않은 정상 상태만의 계산치임을 명시해야 합니다.

### (3) Codex 01 초안의 엄밀성과 과도한 유보
- Codex는 세 에이전트 중 가장 철저하게 `03-feasibility.md`의 검증된 사실만을 근거로 삼았으며, 지어낸 수치가 전무합니다.
- 특히 `04-plan-2weeks.md`의 "1년치 적재 11,784건"조차 03에서 동일 조건으로 검증된 적 없음을 명확히 짚어냈습니다.
- 다만, "성능·가용성의 구체적 방향성"까지 모두 기준선 뒤로 미루어 목표 관리의 지향점이 다소 모호해진 측면이 있습니다.

## 3. 2주 MVP 범위 초과 항목과 빠진 필수 항목

### (1) 범위 초과 항목 (제거하거나 Should/Could로 강등할 항목)
1. **공개 웹 상태 페이지 (`/status`) (Claude FR-14)**:
   - 외부 사용자용 상태 페이지 제작은 2주차 운영 단계에서 추가 화면 작업을 유발합니다. Healthchecks.io 배지와 Grafana 대시보드 스크린샷으로 대체해야 합니다.
2. **복합 인덱스 및 쿼리 50ms 강제 튜닝 (agy NFR-PERF-02)**:
   - 1.2만 건 수준의 데이터에서 인덱스 튜닝은 2주차 성능 점검 시 실행계획(EXPLAIN)을 보고 판단할 일이지, PRD Must 요건으로 50ms를 강제할 필요가 없습니다.
3. **잡알리오 상세 URL 무조건 덮어쓰기 (agy FR-COL-04, Claude FR-06)**:
   - 검증되지 않은 외부 URL 패턴으로 원본 데이터를 영구 치환하는 것은 위험합니다. 원본 `srcUrl`은 그대로 보존하고, 화면 표출 시 보조 링크로 제공해야 합니다.

### (2) 빠진 필수 항목 (최종 PRD에 반드시 포함해야 할 항목)
1. **불완전 수집 시의 안전한 상태 보존 정책 (Codex 지적)**:
   - 외부 API가 일시 장애로 `[]`(빈 배열)을 반환하거나 통신 에러가 났을 때, 기존 진행 공고가 '마감'으로 오인되어 일괄 변경되는 대형 장애를 막는 **"원천 상태 보존 및 유예(Grace Period)"** 규칙이 필수입니다.
2. **호출 예산 서킷 브레이커 (Circuit Breaker)**:
   - 일일 한도 1,000회 중 800회에 도달하면 자동으로 추가 외부 호출을 중단하고 경고 알림을 보내는 안전장치(앱 재시작 시에도 카운터 보존).
3. **기관 식별자(PK) 기준 확정**:
   - 기관코드(`instCd`)가 없는 공고의 처리 기준과 동명 기관에 대한 식별 방침 명시.

## 4. 수용 기준이 검증 불가능한 항목 지적

1. **Claude FR-10(홈), FR-13(기관), FR-16(모바일 레이아웃)**:
   - 수용 기준 컬럼이 완전히 비어 있어, 테스트 코드나 기능 검수 체크리스트로 활용할 수 없습니다. 구체적인 표출 필드와 빈 상태(Empty State) 처리가 명시되어야 합니다.
2. **agy NFR-AVAIL-01 ("배포 중 외부 연속 요청 실패율 0건")**:
   - 부하 발생 조건(요청 주기, 동시 사용자 수, 테스트 도구 k6 스크립트 명세)이 없으면 성공/실패 판정이 불가능합니다. "k6로 1초당 5회 GET 요청을 1분간 전송하는 도중 Blue/Green 전환 시 5xx 응답 0건"과 같이 구체화해야 합니다.
3. **Codex G-01 ("대상 사용자에게 실제 희망 조건으로 탐색을 부탁하고 기록")**:
   - 1인 개발 2주 MVP 배포 전 단계에서는 검증할 수 없는 사용자 정성 평가입니다. 이는 출시 후 운영 과제로 넘겨야 합니다.

   - 목록에서 빠졌다고 바로 마감(CLOSED)시키지 않고, **"마감일자가 지났거나, 정상 응답 목록에서 2회 연속 누락된 경우에만 마감 처리"**하도록 안전장치를 추가합니다.

   - `src_url` 원본 값을 DB에서 임의 변조하지 않고, `original_src_url`로 보존하며 UI 렌더링 시 대체 링크를 함께 제공하는 방식으로 변경합니다.

## 6. 최종 PRD 권고안 (조합 가이드)

### (1) 문제 정의 및 잡알리오와의 차별점 명확화
- **공유 사실 반영**: 잡알리오의 기관비교(`orgcompare.do`)는 경영공시 기반의 '연봉/총 채용규모' 비교에 그치며, 구직자가 필요로 하는 **"특정 직무(전산 등)의 연간 공고 빈도, 실제 채용공고 타임라인, 마감된 과거 공고 상세"**는 제공하지 않습니다.
- **최종 차별점 3요소**:
  1. **직무 맞춤형 즉시 비교**: '정보통신 + 신입 지원 가능' 공고 원클릭 필터링 및 D-3 마감 임박 비교.
  2. **기관별 1년 실제 채용공고 이력**: 단순 연봉 비교가 아닌, 해당 기관이 실제로 1년간 어떤 직무 공고를 냈는지 타임라인 및 직무별 모집 인원 이력 제공.
  3. **운영 신뢰성 및 투명성**: 정제된 원문 링크, 데이터 기준 시각 명시, 수집 신뢰성 증거(무중단 배포 실측, 관측 지표) 공개.

### (2) 최종 Must 기능 요구사항 목록
- **수집 파이프라인**:
  - `FR-COL-01`: 1시간 주기 진행 중 공고 단일 요청(`numOfRows=1000`) 정기 수집.
  - `FR-COL-02`: 공고 내용 해시 기반 변경 감지 및 `posting_change` 이력 적재.
  - `FR-COL-03`: 안전한 마감 판정 (정상 응답 2회 연속 누락 및 마감일 경과 시 마감 전환, 빈 응답 시 상태 보존).
  - `FR-COL-04`: 신규 진행 공고 대상 상세 정보(`/detail`) 수집 (목록의 빈 steps/files로 덮어쓰기 금지).
  - `FR-COL-05`: 최초 1년치 공고 적재 (first_seen_at과 공고 시작일 엄격 분리).
  - `FR-COL-06`: 호출 예산 보호 (일 800회 초과 시 수집 자동 일시중지, 영속 카운터).
- **웹 화면**:
  - `FR-WEB-01`: 홈 `/` (D-3 마감 임박, 오늘 시작된 공고, 정보통신 바로가기).
  - `FR-WEB-02`: 공고 목록 `/jobs` (NCS, 지역, 고용형태, 신입/경력, 진행여부 다중 필터, 검색, 정렬, 페이징).
  - `FR-WEB-03`: 공고 상세 `/jobs/{sn}` (자격, 전형 단계, 첨부파일, 원문 및 대체 링크 안내).
  - `FR-WEB-04`: 기관 이력 `/institutions/{code}` (최근 1년 공고 수, 모집인원 합계, 공고 타임라인 이력).
  - `FR-WEB-05`: 데이터 신뢰성 안내 (모든 화면에 데이터 기준 시각 표기, 깨진 문자/링크 안내).

### (3) 비기능 요구사항 (측정 검증 중심)
- **배포 안전성**: Caddy + Spring Boot Blue/Green 배포. 배포 중 k6(초당 5회 요청) 부하 구간에서 5xx 오류 0건 검증.
- **자원 제약**: OCI A1 (12GB) 환경에서 WAS 힙 각 768MB, 총 메모리 사용량 6GB 이하 유지.
- **보안**: HTTPS 전용, DB/Actuator 외부 차단, 환경변수/Secrets 기반 비밀값 관리 (커밋 유출 0건).
- **백업 및 복구**: 일 1회 Object Storage 자동 백업 및 1회 복원 리허설 수행(소요 시간 실측 기록).
