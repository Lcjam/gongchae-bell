## 1. 라운드 중 확인한 사실

| 사실 | 확인한 사람 | 근거 |
|---|---|---|
| 잡알리오 공고 검색에 NCS, 신입·경력, 고용형태, 지역, **기관명, 진행/마감** 필터와 마감일순 정렬이 있다 | claude, codex | `job.alio.go.kr/recruit.do` |
| 잡알리오 기관 상세에는 소개, 연혁, 조직도만 있고 공고 이력은 없다 | claude | `orginfoview.do` |
| 잡알리오 기관비교에는 5개 탭이 있다: **신규채용현황(연간 신규채용 인원), 청년인턴, 신입사원 초임, 평균보수, 직원수** (경영공시 기반) | agy 제시, **claude 재현 검증** | `POST orgcompare.do` (`apba_id`, `apba_ids`, `st=A~F`) |
| agy의 근거 문서에서 **신입사원 초임(st=C) 수치는 틀렸다.** 실제: 국민건강보험공단 합계 44,451, 대한적십자사 40,306 (agy: 39,077, 32,975). 나머지 4개 탭은 일치. "3/4분기 기준" 표기도 실제 화면에 없다 | claude 재현 | 위와 같음 |
| 기관 식별자로 `pblntInstCd`를 쓸 수 있다 (잡알리오 기관 ID와 같은 형식) | claude | swagger, 실데이터 (03 반영) |
| 11,784건(공시 시작일 기준 1년)과 잡알리오 공고 링크는 실호출로 확인됐다. 03에 기록이 빠져 있던 것을 보완했다 | codex 지적 → claude 보완 | 03 |
| 목록 응답에 자격(`aplyQlfcCn`), 우대(`prefCn`), 전형절차 설명(`scrnprcdrMthdExpln`)이 이미 있다. 상세 API로만 얻는 건 `steps`와 `files`다 | claude | swagger |

**결론: 차별점을 낮춰 잡는다.** 잡알리오는 공고 검색, 마감 공고 조회, 기관별 연간 채용 인원 비교를 이미 제공한다. 우리 서비스의 가치는 **새로운 데이터가 아니라 "흩어진 정보를 한 흐름으로 묶은 편의성"**이다. 조건 목록 → 공고 → 그 기관의 1년 공고 이력, 공고 시기 패턴, 직무 분포를 한 화면에서 이어 보는 흐름이다. 여기에 **데이터 품질 표시**를 더한다. 이 가치는 첫 사용자로 검증할 **가설**이다. 포트폴리오의 핵심 가치는 여전히 운영 기록이다.

## 2. 합의된 결정

| 쟁점 | 결정 | 근거와 출처 |
|---|---|---|
| 문서 형태 | claude의 짧은 구조를 기반으로, codex의 데이터 안전 규칙과 agy의 ID·흐름을 가져온다 | 세 리뷰 모두 같은 의견 |
| 수치 목표 | 확정하는 목표는 두 개뿐이다: **배포 중 고정 외부 시험 실패 0**, **외부 API 일 호출이 한도 1,000 미만**(초기 경고 500, 자동 중단 900은 설정값). 성능, 가용성, RTO, RPO, 수집 성공률은 기준선을 잰 뒤 정한다 | agy 01의 수치(99.9%, 300ms, 15분, 99%, 50ms, 6GB)는 3자 모두 철회 또는 거부했다. codex는 agy의 23/24 = 99% 계산 오류(실제 95.8%)를 지적했다 |
| 마감 판정 | 마감은 **마감일 경과(KST) 또는 API의 `ongoingYn=N`**으로 판정한다. **완결성 검사를 통과한** 수집에서 마감일 전 공고가 빠지면 마감이 아니라 "확인 필요"로 표시한다. 실패, 빈 응답, 잘린 응답은 기존 상태를 그대로 둔다 | codex 제안. claude 동의. agy의 "2회 연속 누락 시 마감"보다 철회된 공고를 마감으로 잘못 표시할 위험이 작다 |
| "오늘 신규" | 공고 시작일 기준. 최초 적재 시각을 쓰지 않는다 | codex. 3자 합의 |
| 신입 필터 | "신입 지원 가능" = R2010 + R2030. "신입만" = R2010 | codex. 3자 합의 |
| 동시 실행 | blue/green 배포 중 앱이 겹쳐도 수집은 1회만 실행한다 (DB 잠금) | codex. claude와 agy도 필수 항목으로 인정 |
| 기관 페이지 | **Must.** 최근 1년 고유 공고 수, 공고 이력, 월별 공고 수(시기 패턴), NCS 분포, "공고상 모집 예정 인원" 합계(숫자로 해석되는 값만 합산하고 나머지는 따로 표시). "실제 채용 실적"이라고 쓰지 않는다. 잡알리오 기관비교의 연간 신규채용 인원은 링크로 안내한다 | 3자 Must 합의. 시기 패턴은 이번 사실 확인 뒤 claude가 추가한 제안 |
| 상세 API | 화면 상세 페이지는 Must. 자격, 우대, 전형 설명은 목록 데이터로 보여 준다. `steps`와 `files`를 위한 상세 수집은 **Should** | 목록 필드 확인으로 codex가 지적한 의존성 충돌이 해소됐다 |
| 원문 링크 | 원본 `srcUrl`은 보존한다. 개별 공고가 아니라고 판별되면 **잡알리오 공고 링크를 함께** 보여 준다 (덮어쓰지 않는다) | agy 02와 codex의 수정안 |
| 깨진 문자 | 복구하지 않고 품질 표시와 원문 안내만 한다 | 3자 합의 |
| 공개 `/status` 페이지 | 제외하고 백로그로 둔다. 대신 모든 페이지에 "마지막 완전 수집 시각"을 표시한다 (Must) | 3자 합의 |
| SEO | title, description, robots는 Must. sitemap과 검색엔진 등록은 Should (04 계획에서 낮춘 부분) | codex 제안, claude 동의 |
| 초기 운영 설정 | 경보: 정기 수집 2회 연속 미완료, 백업 미완료, 웹 외부 감시 실패. 재시도 3회, 백업 일 1회, 보관 14일. 모두 **초기 설정값**이며 근거를 ADR에 남기고 운영하면서 조정한다 | codex("첫날 경보가 없으면 안 된다")와 agy(구체값) |
| 기술 선택 (Java 21/25, 해시 방식, 인덱스 등) | 사용자에게 묻지 않는다. 설계 단계 ADR에서 정한다 | codex |

## 3. 사용자에게 물을 것 (중복 제거, 권고 포함)

| # | 질문 | 권고 |
|---|---|---|
| U1 | "비교"의 의미: 필터와 정렬로 한 목록에서 비교하는 것인가, 공고 몇 개를 골라 나란히 놓고 비교하는 것인가 | **목록 비교**로 한다. 나란히 비교는 백로그 |
| U2 | 차별점이 "새로운 데이터"가 아니라 "편의성 + 품질 표시"라는 점을 받아들이는가. 기관 페이지에 **공고 시기 패턴(월별)**을 넣을 것인가 | 받아들이고 시기 패턴을 넣는다. 데이터를 2~3년치로 늘리면 패턴이 더 의미 있어진다 (API 호출 수십 회로 가능) |
| U3 | GitHub 저장소를 공개로 할 것인가 (무료 ARM64 러너는 공개 저장소에서만 쓸 수 있다) | 공개 |
| U4 | 도메인: DuckDNS 무료 서브도메인인가, 유료 도메인인가 | 둘 다 가능하다. 유료 도메인은 연 1~2만 원대 |
| U5 | CSS: Bootstrap인가, Pico.css인가 | Bootstrap (agy 권고. 컴포넌트가 많다) |
| U6 | 방문 측정: 서버 측 집계(로그와 지표)인가, 외부 분석 도구인가 | 서버 측 집계로 시작한다 (개인정보 최소화) |
| U7 | 첫 사용자를 어디서 모을 것인가 | 사용자 본인이 접근할 수 있는 스터디나 커뮤니티 |

배포 전에 필요한 입력: 운영 알림을 받을 디스코드 웹훅, OCI 밖 백업 사본의 위치.

## 4. 에이전트별 기록 (회고용)
- **codex**: 정확성 규칙(마감 판정, 오늘 기준, 동시 실행, 상세 덮어쓰기 방지)과 수치 검증(23/24 계산 오류)에서 가장 기여했다. 분량 과다는 2라운드에서 스스로 수정 방향을 밝혔다.
- **agy**: 구조와 구현 흐름이 구체적이고, 기관비교 요청 형식을 찾아냈다. 다만 근거 없는 목표치(01), 검색 결과에 기댄 주장(02), **근거 문서 안의 틀린 수치(03의 초임 탭)**가 있었다. **agy가 제시한 수치는 계속 교차 검증한다.**
- **claude**: 잡알리오 기능을 너무 좁게 가정했다(01). 03 문서에 검증 기록이 빠져 있었다. 둘 다 보완했다.
