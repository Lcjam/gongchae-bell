# 알림 자격 교차 검수 · codex

2026-11-17. root·agy·Sol의 독립안과 agy의 교차 검토를 읽었다. 기존 불변 코드에서 목록 open은 OPEN/CHECK, 홈 마감 임박은 OPEN만이고, CHECK는 완전 응답에서 빠졌으나 명시 종료나 마감이 확인되지 않은 상태라는 사실은 일치한다. 두 안 모두 가능한 정책이며 기존 PRD가 OPEN-only를 명시했다고 확대하지 않는다.

## root 독립안의 수정

root의 OPEN/CHECK 포함 초안을 철회하고 **OPEN이면서 KST 오늘 이상 마감**인 공고만 알림 후보로 삼는 안을 수용한다. 목록에서 경고를 보고 직접 탐색하는 동작과, 현재 접수 여부를 확인하지 못한 공고를 능동적으로 보내는 동작의 차이가 근거다. 기존 홈 마감 임박도 후자의 기준에 가까운 OPEN-only를 사용한다. 필터·설정·본문 상태 경고 정책을 새로 추가하지 않고 현재 MVP의 명시적으로 진행 중인 공고를 알린다는 의미를 유지한다.

이는 다른 두 의견의 수로 결정한 것이 아니다. CHECK를 포함하면 일시 누락의 D-3를 보존한다는 root 반례는 여전히 맞지만, 조기 철회 가능성이 있는 상태를 정상 알림 대상으로 승격하는 선택도 함께 필요하다. 원천 누락 빈도나 조기 철회 비율은 실측하지 않았으므로 어느 쪽이 현실에서 더 자주 발생한다고 주장하지 않는다. OPEN-only의 기회 손실(특히 그날 D-3)은 결과 문서에 남긴다. CHECK를 CLOSED로 바꾸거나 목록에서 숨기지는 않는다.

## 공통 불변식

정기 최초 INSERT만 Discord NEW outbox를 만들고, backfill·재등장·변경 관측은 NEW를 새로 만들지 않는다. 이메일 NEW의 활성화 시각 하한/non-backfill/미중복 조건과 D-3 종류의 중복키를 유지한다. 모든 현재 자격 검사에서 지난 마감과 CLOSED를 배제한다. unknown 뒤 target set이 바뀌면 hash가 같아도 R/HTTP 없이 UNCERTAIN·item 보존이며, target이 같아도 전체 payload hash가 달라지면 같은 키로 보내지 않는다.

## D-3의 오늘과 batch 날짜를 구분할 것

Sol 독립안이 지적한 **현재 자격은 KST 실행일 기준, 본문 결정성은 batch 날짜 기준**을 구별해야 한다. ADR-0003은 만회 마감 임박을 실행일 기준 D-3만 보낸다고 적었다. 따라서 전날 batch의 작업을 자정 뒤 재시도할 때 `end_date = batchDate + 3`만으로 계속 D-3라고 판정하는 것은 위험하다. 생성·TX2에서 현재 KST 오늘+3을 확인하고, 과거 batch 날짜를 현재 자격의 근거로 고정하지 않는 쪽이 기존 ADR/현재 재확인 계약과 맞는다.

agy 준비표의 batchDate+3 표현은 생성 당시에는 오늘과 같지만 자정 넘긴 TX2에서 달라질 수 있으므로 교차 확인 후 수정한다. 새 일정·추가 만회·D-2 재알림은 넣지 않는다. unknown 작업에서 D-3가 아닌 항목이 생기면 기존 target 변경 규칙으로 처리하며, 본문 날짜를 현재 시각으로 바꿔 멱등성을 깨지 않는다.

이번 문서는 코드 변경·새 설정·실제 실행 검증이 아니다. 남은 교차 확인 후 짧은 종합 파일로 #7 작성자에게 전달한다.
