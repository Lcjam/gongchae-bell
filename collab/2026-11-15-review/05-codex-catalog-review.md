# #5 웹 구현 1차 검수 · codex

대상: `feat/#5-catalog-web`, 구현 커밋 `13daeacc1c395af7374b33ea05ac82489c22e68a`. 읽은 근거: catalog Java 전체, 홈/목록/상세/기관/공통/오류 템플릿, CatalogUnitTest와 CatalogIntegrationTest, 구현 결과 보고서. 구현자가 완료한 상태를 확인한 뒤 검수했다.

## 수정 요청

1. **FR-W5 오류 페이지 기준 시각 누락**: CatalogController의 자체 404 처리만 freshness를 넣는다. `/does-not-exist` 같은 Boot 기본 오류 경로와 일반 error.html은 lastCollected가 없어 실제 COMPLETE가 있어도 '아직 완전 수집 기록이 없습니다'로 표시된다. 실제 Error dispatch에도 기준 시각을 공급하되 DB 장애 때 오류 화면이 재귀 실패하지 않도록 처리하라. 실제 HTTP로 알 수 없는 경로 404 및 일반 오류 경로를 확인하고, 기존 COMPLETE 시각이 표시되는지 검증하라.
2. **자동 테스트가 수용 기준을 충분히 증명하지 않음**: 목록 테스트는 region/hire/newonly/career 필터 결과를 확인하지 않고, 정렬은 `sort=begin` 문자열만 확인한다. NCS 중복도 정확한 결과 건수/ID를 확인하지 않는다. DB 조회 결과 또는 HTML을 구조적으로 검사해 실제 필터·정렬 순서·페이지 간 중복 없음·직무별 고유 수·연도별 모집 인원/비숫자 제외 수를 검증하라. 테스트 수를 늘리는 것이 목적이 아니라 기존 수용 기준을 정확히 증명해야 한다.
3. **동적 기준 시각/지연 상태**: 출시 조건에 지연 상태 확인이 있다. 최근 COMPLETE 후 수집 실패 시 timestamp 유지뿐 아니라 데이터가 오래됐음을 사용자가 알아볼 수 있는 안내를 기존 Clock으로 구현하고 기준/회복을 검증하라. 초기 경보인 2시간과 맞추는 단순 기준으로 충분하며 설정 계층을 늘리지 않는다.
4. **제품에 구현 단계 노출**: 홈과 목록의 `M2` 표현을 제거하라. 사용자에게는 '알림 준비 중'이면 충분하다. 알림 기능 활성화는 M2 담당 작업이다.
5. **검증 보고서 정확성**: SafeUrlValidator는 사설/예약 IP를 차단하지 않으며 layout에는 canonical도 없고 목록에는 학력 필터가 없다. 결과 파일의 구현 목록을 실제 코드에 맞게 수정하라. 원문 링크는 브라우저 이동이므로 Discord SSRF 정책을 가져와 불필요하게 제한하지 않는다. 현 웹 URL 검증은 이 범위에서 수용한다.
6. **브라우저 검증 경로**: 이 프로젝트에서는 Orca embedded browser를 사용한다. 원시 Chrome CDP 대신 orca-cli 스킬의 browser reference를 읽고, 실제 목록→상세→기관 탐색 및 360px 필터 토글을 확인해 스크린샷/관측 근거를 전용 결과 파일에 남겨라. 이미 통과한 자동 테스트를 무의미하게 반복하지 말고 이번 수정 영향과 미확인 흐름을 확인한다.

## 연동 대기 (이번에 임의 변경하지 않음)

- #3 우대 두 원문 저장 형식은 조율자가 공개 계약을 검수 중이다. 현재 U+001F 표현을 그대로 UI에 출력하는 연결은 승인하지 않는다. #3 수정 계약 도착 후 함께 확인한다.
- #4가 V3를 추가하므로 #3 공용 통합 테스트 기반과의 합본 테스트가 필요하다. 기존 V1/V2는 수정하지 않는다.
- 실제 상세 필드의 steps/files는 #4 계약과 연결해 후속 교차 리뷰에서 확인한다. 임의 필드 추측만으로 실제 API를 검증했다고 표시하지 않는다.

원격 CI와 구현자 외 두 리뷰가 남아 있다. 본 검수는 수정 후 재확인이 필요하며 머지 승인이 아니다.
