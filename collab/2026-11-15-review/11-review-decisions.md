## 적용할 수정

1. root 검수의 완료 월 SN 집합 스냅숏, unlock 실패 시 물리 연결 폐기, 실패 페이지 반영 전 의미 검증을 모두 처리한다. 기존 #3 계약 때문에 사후 검증을 할 수밖에 없다는 해석은 철회한다. 단일 파싱을 유지하며 검증과 쓰기를 분리하거나, 코어 트랜잭션 안에서 요청 범위·수신 크기·중복 검사까지 끝내는 최소 계약 확장을 #3에서 먼저 구현한다. 최초 적재가 실패했다고 정상 공고 내용까지 바꿔서는 안 된다. 기존 API를 유지해야 할 실사용자는 아직 없으므로 불필요한 호환 래퍼는 만들지 않는다.
2. 상세의 끝없는 시간별 재시도(H1)는 수용할 수 없다. 상세 대상별 실패 제한, sweep당 건수/시간 제한, 정기 수집 호출 몫 보존을 함께 검토해 정기 수집을 굶기지 않는 정책으로 구현·문서화한다. 구체 초기값은 구현자가 제안하되 ADR-0014와 일치시킨다. 같은 DB 카운터에서 원자적으로 상세용 예산 여유를 확인해야 한다. 상한에 걸린 공고의 미수집/실패 표시를 숨기지 않는다.
3. 큰 Retry-After는 서버 지시보다 일찍 재시도하지 않는다. 예: 지시가 인라인 허용 대기 60초를 넘으면 자지 않고 고정 HTTP_RATE_LIMIT 실패로 회차를 끝내 다음 회차에 맡긴다. 값을 60초로 잘라 조기 재요청하는 구현은 금지한다. 큰 초/HTTP 날짜/비정상 헤더 경계를 검증한다.
4. 상세 sweep의 시간·건수 상한으로 정기 스케줄을 장시간 붙잡지 않도록 하고, 스케줄러 종료 대기 30초를 설정한다. 풀 크기만 늘려 동기식 같은 cron 작업의 겹침이 자동 해결된다고 주장하지 않는다. 항상 INVALID_DETAIL인 대역으로 여러 슬롯을 실행해도 정기 호출 몫이 남는지 검증한다.
5. 운영 문서에 '최초 적재 완료 후 정기 수집 활성화' 순서를 명시한다. API 원문 검증/빈 달 응답/운영 500 경보 수신 미완료는 계속 별도 게이트로 남긴다.
