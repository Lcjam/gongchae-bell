# PR #9 수집 코어 검수 · codex

대상: 구현 `4b5c44261536a299cf004ff8cad45e8a3880f3e5`, 결과 문서 포함 최신 `4cca391d2333d4762135e2fd06298855da38b07e`. 두 커밋의 CI test/secrets 성공 확인. 파서, PostingIngestor, 공개 계약, 파서·반영 통합 테스트, 결과 보고서를 대조했다.

실패 행을 사전에 검증해 전체 반영을 막는 점, 성공 반영과 회차 마감을 한 트랜잭션으로 묶은 점, 상세 컬럼 미갱신, 정렬된 잠금 및 충돌 재읽기는 수용한다. 아래 수정 후 재검수가 필요하다.

## 수정 요청

1. **페이지 SN 집합 연동**: `Counts.totalCount/received/inserted`만으로는 월 고유 수와 페이지 간 중복을 검증할 수 없다. `inserted`는 이미 저장된 공고를 빼기 때문에 수신 고유 수가 아니다. `upsertPage`가 검증·반영한 공고 SN 집합을 불변 결과로 반환하도록 공개 계약을 확장하라. 같은 본문을 #4에서 다시 파싱하지 않게 한 번 파싱/한 번 반영 경계를 유지한다. 반환 객체 이름은 구현자가 정하고 계약을 먼저 갱신한다. 같은 페이지 두 번 및 기존 DB 공고가 있어도 SN 집합과 수신 고유 수가 정확함을 테스트하라. #4 담당 Sol이 이 결과를 대기 중이다.
2. **우대 사항의 제어문자 형식**: U+001F가 포함된 정상 원천 문자열을 INVALID_ROW로 거부하는 제약은 원천 API에 확인되지 않았다. 사용자 화면에 제어문자를 출력하거나 #5에게 숨은 split 계약을 강제하지 말고, 두 원문의 내용을 보존하는 라벨/줄바꿈 기반의 사람이 읽을 수 있는 안정된 표현 등으로 수정하라. 각 원문 변경의 관측 테스트는 유지한다. U+001F 때문에 전체 수집이 막히지 않는 테스트를 추가하고 계약/ERD를 일치시킨다. 별도 구조나 컬럼이 꼭 필요하다고 판단하면 구현 전 근거를 질문으로 보낸다.
3. **APPLY_ERROR 검증 누락**: 보고서에서 미검증이라고 명시한 예외 경로는 FR-C2의 공고 무변경과 회차 실패 기록을 지키는 핵심이다. 통합 테스트에서 일시적인 CHECK 제약 또는 트리거로 중간 행 쓰기 오류를 일으켜 공고/기관/코드/변경 전체 롤백, 기존 COMPLETE 시각 유지, 해당 회차 FAILED/APPLY_ERROR 마감 및 예외 재전파를 검증하라. 테스트용 제약은 finally에서 정리한다.
4. **Flyway 테스트 미래 호환**: #4에 V3가 예약돼 있다. FoundationIntegrationTest의 마이그레이션 성공 건수 `=2` 고정은 합본에서 실패한다. V1/V2 존재 및 실패 이력 없음 등 해당 테스트가 실제 보장해야 할 조건으로 바꾸고 전체 성공 건수를 고정하지 않는다. 기존 V1/V2는 수정하지 않는다.
5. **신뢰 경계**: totalCount 음수를 INVALID_ENVELOPE로 거부하라. 정기 수집은 건수 불일치로 걸리지만 최초 적재 페이지는 현재 음수 전체 건수를 정상 반환할 수 있다. 음수 fixture 테스트를 넣는다.
