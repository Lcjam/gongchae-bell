## 지적 사항

### P2 · D1: 운영 문서가 제거된 설정과 이전 보관 정책을 안내한다

대상은 `docs/ops/backup-restore.md:23`의 §2, `:36`의 보관량 설명, `:65`의 `BACKUP_KEEP_DAILY` 행, `:107`의 실패 경로, `:154`의 PC 후속 작업이다.

ea9d0ca 문서는 여전히 백업 성공 뒤 `--keep-daily 14 --prune`을 실행한다고 안내한다. 실제 코드는 덤프 전에 실행 UTC 기준 14일 초과 ID를 삭제하고 매번 `prune --max-unused 0` 및 재조회를 수행한다. 특히 운영자가 env 표를 따라 `BACKUP_KEEP_DAILY=14`를 넣으면 `backup.sh:251`의 검증에서 실행이 거부되어 백업과 만료가 모두 수행되지 않는다. 문서만 보고 운영할 수 있어야 한다는 DoD와도 어긋난다.

재현 조건은 기존 env 또는 문서대로 만든 env에 `BACKUP_KEEP_DAILY=14`가 있는 경우다. 코드와 `backup-test.sh:304`의 기존 회귀가 이 실패를 명시한다. 새 실행으로 반복하지 않았다.

최종 문서에는 고정 14일 초과·마지막 0개 허용, 만료→prune→재조회→덤프 순서, 제거된 env의 이행 방법, 실패 동안 물리 삭제 지연 및 재실행 절차를 반영해야 한다. 이는 Claude 결과 문서에 이미 남긴 미완료 사항이므로 별도 새 기능 요구가 아니다.

### P2 · D2: PC 접점의 copy 우선 순서가 네트워크 실패일의 로컬 만료를 놓친다

대상은 `docs/adr/0017-backup-wall-clock-retention.md:17`이다. 현재는 OCI에서 `restic copy`로 가져온 **뒤** 로컬 만료를 돌리는 순서만 제안한다.

PC에 20일 된 사본이 있고 OCI 연결 또는 copy가 실패하는 경우, 이 설명대로 성공한 copy 뒤에만 정리를 붙이면 기존 로컬 사본은 다시 남는다. 사용자 결정 `collab/2026-11-19-recovery/04-user-retention-decision.md`는 실패한 백업·네트워크 상태에서도 로컬 정리를 실행할 수 있는 순서를 명시했다. 따라서 접점에 **로컬 만료·prune를 네트워크 작업 전에 수행하고, copy된 오래된 사본도 잔류하지 않도록 후속 정리·검증한다**는 조건이 필요하다. PC 코드 구현이나 운영 저장소 구축을 이번 PR에 추가하라는 지적은 아니다.

이는 ADR과 사용자 결정의 흐름 비교에 따른 지적이다. PC copy 실패를 실제 실행한 결과는 아니다.

### P3 · O1: 삭제 뒤 재조회 실패도 “nothing was deleted”라고 기록한다

대상은 `deploy/backup/backup.sh:399`, `:403`, 그리고 동일 함수를 다시 부르는 `:424`다.

첫 조회→forget→prune가 성공하고 두 번째 snapshots 호출 또는 selector만 실패하면, 실제로 만료 사본이 삭제됐어도 `/fail` 본문과 로그가 `nothing was deleted`라고 말한다. 재조회 실패를 성공으로 세거나 덤프를 계속하는 문제는 없지만, 마지막 사본이 남아 있는지 판단하는 운영자에게 부정확한 정보다. `forget`의 비정상 종료도 부분 삭제 가능성이 있으므로 `:418`의 “snapshots are still listed”는 전체가 그대로라는 보장으로 읽지 않아야 한다.

두 번째 호출에만 실패를 주는 제어 흐름을 코드로 확인했다. 해당 실패 주입은 실행하지 않았다. 상태 미확인·이미 삭제됐을 수 있음을 전달하는 표현으로 정리할 수 있는 비차단 관찰이며, 별도 코드 개선 작업을 구현자에게 요청하지 않았다.

## 직접 수행한 제한 검증

2026-11-20 Windows Python **3.12.10**, 지정 SHA의 selector를 `python -I` subprocess로 호출했다. 저장소·설정·시험 파일을 수정하지 않았다. 기존 Linux 전체 시험이나 Docker 통합 시험은 반복하지 않았다.

- 8개 입력 오류: 잘린 JSON, 뒤에 JSON이 추가된 입력, 비객체 항목, 숫자 ID, 숫자 시각, 문자열 tags, 존재하지 않는 날짜, ID 누락. 각 목록은 앞에 유효한 만료 사본을 포함했고, 모두 **exit 2 + stdout 빈 값 + RETENTION_INPUT_INVALID**였다.
- 정각 14일과 정각보다 1나노초 늦은 시각은 모두 `expire=0`이었다.
- 위 제한 검증은 **10/10 통과**했다. 전체 단위·통합 시험을 실행했다는 뜻은 아니다.
